# 課題リスト：バグ修正と機能改善

> **対象読者**：受講者（ペアプロで取り組む）
> **所要時間**：55 分（ハンズオン⑨）
> **形式**：2 人 1 組（同じ課題に各自チャレンジし、過程を共有し合うスタイル）

---

## ペアプロ進行ルール

- **各自でチャレンジ**：基本は自分の PC で同じ課題に取り組む。プロンプトも修正方針も、自分で考えて投げてみる
- **共有タイム**：1 つの課題が終わる（または詰まる）ごとに、**どんなプロンプトを投げたか／どんな問題が起きたか／どう解決したか**を画面を見せながら共有する
- **一緒に試行錯誤**：詰まったら抱え込まず声を掛ける。相手のプロンプトを自分の環境で試してみるのも歓迎
- 必須ライン：
  - **B1〜B2 のバグ修正**
  - **F1〜F3 のいずれか 1 件に着手**（完成しなくて OK）
- **Plan モード** と **Agent モード** を意識的に使い分けること
- 終了 10 分前に手を止め、「使ったプロンプト」「効いた工夫・効かなかった工夫」をメモにまとめる（全体への共有は振り返りの時間に行います）

> **注**：再現・動作確認はすべてブラウザ（http://localhost:5000）の画面操作で行います。

---

## バグ一覧（必須・全 2 件）

### 🐛 B1：完了済み TODO が削除できない（難易度：★☆☆）

**症状**
- 完了マークを付けた TODO を削除しようとすると失敗する
- 未完了の TODO は問題なく削除できる

**再現手順**
```text
1. ブラウザで http://localhost:5000 を開く
2. 「設計書を書く」（完了済み）の削除ボタンを押し、確認ダイアログで OK を押す
3. アラートに「not found」が表示され、削除されない
```

**期待動作**
- 完了済みかどうかにかかわらず、対象の TODO が削除され、一覧から消える

**推奨アプローチ**：Agent モードで修正 ＋ 類似バグの横断探索

---

### 🐛 B2：空文字タイトルで保存できる（難易度：★☆☆）

**症状**
- 編集ダイアログでタイトルを空文字 or 空白だけにして保存ボタンを押すと、保存できてしまう
- 一覧で「タイトルが空」の TODO が表示される

**再現手順**
1. 任意の TODO の編集ボタンを押す
2. タイトル欄を空文字にする（または半角スペースのみ）
3. 保存ボタンを押す
4. 一覧でタイトルが空白の TODO が表示される

**期待動作**
- サーバ側で `title` が空文字 or 空白のみなら 400 を返す
- フロント側でも保存ボタンが押せない（または送信前にチェックしてメッセージを表示）

**推奨アプローチ**：Plan モードで仕様確認（バリデーションをサーバ・フロント両方に入れるか）→ Agent モードで実装

## 機能改善要望（最低 1 件・できれば全部）

### ✨ F1：期限日（due_date）フィールド追加（難易度：★★☆）

**要件**
- TODO に `due_date` (YYYY-MM-DD) フィールドを追加
- 新規追加・編集の UI に日付ピッカー
- 一覧表示で期限を表示
- 期限切れ TODO は赤色のバッジを表示

**変更箇所**：`db/init.sql`（or マイグレーション）、`server.py`、`public/index.html`、`public/app.js`

---

### ✨ F2：優先度（priority）追加 + 色分け（難易度：★★☆）

**要件**
- `priority` カラム（`high` / `medium` / `low`、デフォルト `medium`）
- 新規追加・編集の UI に選択肢
- 一覧で優先度バッジを色分け表示（high=赤、medium=橙、low=緑）

**変更箇所**：`db/init.sql`、`server.py`、`public/*`

---

### ✨ F3：CSV エクスポート機能（難易度：★★☆）

**要件**
- ヘッダーに「CSV エクスポート」ボタンを配置
- クリックで全 TODO を CSV としてダウンロード
- ヘッダ行：`id,title,description,completed,created_at,updated_at`
- 文字化けしない（UTF-8 with BOM 推奨）

**変更箇所**：`server.py`（`/api/export.csv` エンドポイント追加）、`public/index.html`、`public/app.js`

## プロンプトテンプレ（コピペ用）

### バグ B1 の起点プロンプト

```text
samples/session3/todo-app-buggy 配下の TODO アプリを修正してください。

## 現状
ブラウザで完了マークを付けた TODO を削除しようとすると、
アラートに「not found」と表示され、削除できない。

## 期待
完了状態にかかわらず削除できる。

## 依頼
1. 原因を特定し、修正パッチを提案してください
2. 同じ DELETE エンドポイントに他の潜在バグがないか確認してください
3. 検索や更新エンドポイントなど、他にも類似のバグがないか
   横断的にチェックしてください。ただし見つかったものは
   修正せず、一覧で報告だけしてください（この後の課題で自分で直します）
4. 修正の単体テストも提案してください（pytest）
```

> **なぜ「報告だけ」と書くのか**：これを書かないと、Agent が B2 に相当するバグまでこの 1 往復でまとめて修正してしまい、後続の課題（Plan モードの練習）が消えてしまうためです。探索範囲だけでなく、どこまで手を動かしてよいかもプロンプトで制御できます。

> **なぜディレクトリを指定するのか**：冒頭で `samples/session3/todo-app-buggy 配下` と指定しておくと、Copilot が配下の `server.py` や `public/` のファイルを自分で探して読んでくれます。

### Plan モードで F1 を計画させる

```text
samples/session3/todo-app-buggy 配下の TODO アプリに
「期限日 (due_date)」フィールドを追加したいです。

要件:
- フィールドは YYYY-MM-DD 形式、optional
- 新規追加・編集の UI に日付ピッカー
- 一覧で期限を表示、期限切れは赤バッジ
- 既存データのマイグレーションも考慮

実装計画を立ててください。
- スキーマ変更
- API 変更（GET/POST/PUT のリクエスト/レスポンス）
- フロントエンドの変更点
- テスト戦略
```

### Bxx の根本原因と修正後の動作確認をペアでレビュー

> `Bxx` の部分は、実際に取り組んだバグの**症状の説明**に置き換えて送信してください（例：「完了済み TODO が削除できないバグ」）。

```text
samples/session3/todo-app-buggy 配下の server.py にある Bxx に対する
修正 PR を作るとして、以下の観点でセルフレビューしてください。

1. 修正は最小限か（不要なコード変更がないか）
2. テストケースは妥当か（境界値・異常系を含むか）
3. 既存の他エンドポイントに影響しないか
4. ドキュメント更新は必要か
```
