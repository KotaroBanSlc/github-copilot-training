# Pythonコードの検証Harness

- 作業範囲は、現在開いているgenerate_harness内に限定する。他の演習フォルダや教材は変更しない。
- 通常の開発依頼で変更する対象はorder_summary.pyだけとし、集計処理とformat_summaryの戻り値の形式を保つ。
- Harnessの構築・改善を明示的に依頼された場合は、scripts/check_all.py、scripts/check_no_print.py、このinstructionsの作成・修正を許可する。その場合も対象コードや規約を勝手に変更しない。
- H1ではruffを実行する入口を作成し、H2でこの検証手順を整備し、H3で独自Scriptを同じ入口へ追加する。templatesは構築後の比較用であり、参照・コピーではなく仕様から作成する。
- コードの規約はこのinstructionsに書かず、検証コマンドが判定する。ruffの規約はpyproject.toml、独自のルールはscriptsフォルダの検証Scriptが持つ。
- 依頼された変更でorder_summary.pyを変更したら、直後に下の検証コマンドをターミナルから直接実行する。違反の有無は検証結果で判断し、結果を予測して依頼内容を変えたり、実行を省略したりしない。対象Pythonファイル自体は実行しない。
- 検証だけを依頼された場合や修正しないよう指定された場合は、違反を検出しても対象コードを修正しない。
- 終了コード0で、登録した検証がすべて成功した場合だけ検証成功とする。H1・H2はruffだけでPassed 1/1、H3は独自Scriptを追加してPassed 2/2となる。終了コード1は違反、2は検証エラーとして区別する。
- 終了コード1の場合は、出力された対象箇所と対応方法に従ってorder_summary.pyを修正し、同じコマンドで再検証する。依頼の目的は保ち、違反の修正に必要な範囲だけを変更する。
- 修正と再検証は3回までとする。それでも終了コード0にならない場合は、残った違反を報告して停止する。
- 動作確認や通常の開発で検出された規約違反はorder_summary.py側で修正する。検証Script、instructions、pyproject.tomlを変更して判定を回避しない。構築時の改善でも、検証を削除・弱体化したり、# noqaや別名・属性経由の呼び出しで回避したりしない。
- 終了コード2の場合や、Scriptがない、Pythonを起動できない、出力や終了コードを確認できない場合は、未検証として原因を報告し、停止する。
- Hookは使用せず、設定の作成・変更・有効化や発火確認を行わない。既存の安全対策も無効にしない。
- 最終報告に、変更内容、各回の検証コマンドの出力と直後の終了コード、検出された違反と修正内容を含める。検証結果に従って依頼と異なる実装にした場合は、その理由を明記する。説明や目視確認だけで検証済みとしない。
- これはinstructionsに従う直接実行であり、保存時の自動実行やHookによる強制停止ではないことを明記する。

## 検証コマンド

generate_harnessを作業ディレクトリとして、Windows PowerShellで実行する。3階層上の教材ルートにある共通の.venvを使い、この演習フォルダに仮想環境を作成しない。終了コードまで同じ実行の出力に残すため、外側の & { ... } を含むブロック全体を1回のターミナル呼び出しで実行する。

```powershell
& {
	$ErrorActionPreference = 'Stop'
	..\..\..\.venv\Scripts\python.exe -B ./scripts/check_all.py
	$validationExitCode = $LASTEXITCODE
	Write-Output "ExitCode=$validationExitCode"
}
```
